# انتقال استراتژی‌ها به ربات معامله‌گر

این سند برای ایجنتی است که در ریپوی ربات معامله‌گر کار می‌کند. همه‌چیزِ لازم
برای پیاده‌سازی اینجاست؛ نیازی به خواندن ریپوی پژوهش نیست.

## ۰) فایل را بردار

```bash
curl -O https://raw.githubusercontent.com/Morashidian8/Tictactoestevie/main/strategies.py
```

بدون وابستگی است — فقط کتابخانهٔ استاندارد پایتون. آن را **تغییر نده**؛ اعدادش
روی ۱۶۲٬۴۴۷ کندل واقعی اندازه‌گیری و صحت‌سنجی شده است.

## ۱) بازار و تعریف تسویه

- **بیت‌کوین، کندل ۵ دقیقه‌ای**، بازارِ بالا/پایینِ پلی‌مارکت
- تسویه: **قیمت بسته‌شدنِ پنجره در برابر قیمت بسته‌شدنِ پنجرهٔ قبل**
  (close-to-close). نه high/low، نه open.
- پنجرهٔ `[T, T+300)` با قیمت لحظهٔ `T+300` بسته می‌شود. یعنی نمونه‌ای که
  درست بعد از مرز می‌گیری، **بسته‌شدنِ پنجرهٔ قبلی** است و شرطی که تولید
  می‌کند روی پنجره‌ای است که همین الان **باز شده** — همان که هنوز می‌شود
  واردش شد.

## ۲) حلقهٔ اصلی

```python
import time, json
from strategies import evaluate, Book

GRAN = 300          # ۵ دقیقه
LAG  = 2            # ثانیه صبر بعد از مرز تا اوراکل قیمت را منتشر کند

closes = load_last_140_closes()      # قدیمی → جدید، بدون حفره
book   = Book(load_state())          # state = {} بار اول
open_bets = {}                       # stream -> (side, ref_price)

while True:
    now = time.time()
    nxt = (int(now) // GRAN + 1) * GRAN
    time.sleep(nxt + LAG - now)      # روی مرز بیدار شو، نه هر N ثانیه

    price = fetch_price()            # ← بخش ۳
    closes.append(price)
    closes = closes[-140:]

    # ۱) شرط‌های بازِ پنجرهٔ قبل را تسویه کن
    for stream, (side, ref) in list(open_bets.items()):
        if price == ref:             # مساوی = بی‌نتیجه، نه باخت
            del open_bets[stream]; continue
        won = (side == "up") == (price > ref)
        book.settle(stream, won)
        del open_bets[stream]

    # ۲) سیگنال‌های جدید
    for sig in evaluate(closes, streams=("rule6", "golden")):
        stake = book.stake(sig.stream)
        place_paper_order(side=sig.side, size=stake,
                          window_start=nxt, note=f"{sig.name} — {sig.detail}")
        open_bets[sig.stream] = (sig.side, price)

    save_state(book.state())
```

**چرا خواب تا مرز و نه پولینگِ هر ۲۰ ثانیه:** تأخیر تمامِ ماجراست. شرط باید در
ثانیه‌های اولِ پنجره بسته شود، قبل از اینکه بازار حرکت را قیمت‌گذاری کند. با
پولینگِ ۲۰ ثانیه‌ای، هشدار تا ۲۰ ثانیه دیر می‌رسد و قیمت رفته است.

## ۳) فید قیمت

پلی‌مارکت روی **Chainlink BTC/USD** تسویه می‌کند، نه Binance. اگر ربات فعلی
از Binance می‌خواند، سطوح با تسویهٔ واقعی درِفت می‌کنند (اختلافِ اندازه‌گیری‌شده
تا ۱۵ دلار). Chainlink بدون هیچ وابستگی، با یک `eth_call` روی Polygon:

```python
import requests
RPCS = ["https://polygon-bor-rpc.publicnode.com",
        "https://polygon.llamarpc.com",
        "https://polygon-rpc.com"]
FEED = "0xc907E116054Ad103354f2D350FD2514433D57F6f"   # BTC/USD روی Polygon

def chainlink_btc():
    for url in RPCS:                      # نقاطِ عمومی می‌آیند و می‌روند
        try:
            r = requests.post(url, timeout=10, json={
                "jsonrpc": "2.0", "id": 1, "method": "eth_call",
                "params": [{"to": FEED, "data": "0xfeaf968c"}, "latest"]})
            raw = r.json()["result"][2:]
            answer = int(raw[64:128], 16)          # latestRoundData().answer
            if answer >= 1 << 255:                 # int256 مکملِ دو
                answer -= 1 << 256
            updated = int(raw[192:256], 16)        # updatedAt
            return answer / 1e8, updated           # فید ۸ رقم اعشار دارد
        except Exception:
            continue
    raise RuntimeError("no RPC answered")
```

اولین نقطه‌ای که جواب داد را برای دفعات بعد نگه دار (failover چسبنده). اگر
پاسخ بیش از ۲ پنجره کهنه بود، کندل را ثبت نکن و چند ثانیه بعد دوباره بگیر.

## ۴) جریان‌ها و نردبان‌ها

| جریان | چیست | سیگنال/روز | دقتِ اندازه‌گیری‌شده | پایهٔ پیشنهادی |
|---|---|---|---|---|
| `rule6` | AABA + RSI(14) ≥ ۷۰ ← پایین | ۱٫۳ | ۵۹٫۷٪ (محافظه‌کارانه ۵۷٪) | ۵۰$ |
| `golden` | ۳ قانونِ آماریِ هم‌نظر + کشیدگیِ ≥۹× | ۳٫۷ | ۵۵٫۷٪ | ۲۰$ |
| `statistical` | هر وقت قانون‌های ۱/۲/۳/۵ هم‌نظر شدند | ۵۶٫۶ | ۵۳٫۷٪ | ۲۰$ |

### دربارهٔ `statistical` — بخوان قبل از روشن‌کردنش

پیش‌فرضِ `evaluate` فقط `("rule6", "golden")` است. `statistical` عمداً بیرون
گذاشته شد چون **۵۶٫۶ معامله در روز** است — یکی هر ۲۵ دقیقه، ۲۴ ساعته — و برای
دستِ آدم اجراشدنی نیست. برای رباتِ خودکار در حالت کاغذی این ایراد وارد نیست،
پس روشن‌کردنش منطقی است:

```python
evaluate(closes, streams=("rule6", "golden", "statistical"))
```

ولی این دو را بدان:

1. **بدترین افتش ۵٬۱۰۰ دلار با پایهٔ ۵۰ است.** با پایهٔ ۲۰ می‌شود ۲٬۰۴۰ دلار.
   برای پول واقعی با سرمایهٔ ۱۸۰۰ دلار، پایهٔ ۵۰ روی این جریان ورشکستگی است.
2. **عددِ سودش با پول واقعی تکرار نمی‌شود.** روی ۲۰٬۶۶۱ معامله، حتی ۲ سنت
   اسپرد یا کارمزد کلِ سود را می‌بلعد. در حالت کاغذی که کارمزد صفر است، این
   جریان بهترین به نظر می‌رسد — و همان‌جا بیشترین گمراهی را می‌سازد. اگر
   شبیه‌ساز کارمزد/اسپرد دارد، حتماً روشنش کن قبل از قضاوت.

`golden` زیرمجموعهٔ سخت‌گیرانهٔ همین جریان است: همان قانون‌ها، ولی فقط وقتی
دست‌کم سه‌تایشان هم‌نظرند و کشیدگی ≥۹× است. اگر یکی را می‌خواهی، `golden`
انتخابِ کم‌ریسک‌تر است.

مارتینگل: **۳ پله**، `پایه, ۲×, ۴×`. هر برد چرخه را می‌بندد و خالص `+پایه`
می‌دهد. سه باختِ پیاپی = انفجار (`-۷× پایه`) و نردبان ریست می‌شود.

> **قانونی که نباید بشکنی:** هر جریان نردبانِ کاملاً مستقلِ خودش را دارد. اگر
> `rule6` روی پلهٔ ۳ است و `golden` سیگنال داد، آن یکی از **پلهٔ ۱** شروع
> می‌کند. `Book` این را تضمین می‌کند — دستی قاطی‌شان نکن. روی ۱۲ ماه، نردبانِ
> مشترک ۱۴٬۶۵۰ دلار داد و دو نردبانِ جدا با **همان سیگنال‌ها** ۱۸٬۱۵۰ دلار.

استراحت بعد از انفجار **لازم نیست** — تست شد: همان تعداد انفجار، فقط ۸۵۰ دلار
سود کمتر.

## ۵) معیارِ پذیرش

بعد از پیاده‌سازی، ماژول را روی دادهٔ تاریخی اجرا کن. اگر این اعداد درنیامد،
جایی از اتصال غلط است:

| جریان | شرط | دقت | سود (پایه ۵۰$) | انفجار | بدترین افت |
|---|---|---|---|---|---|
| `rule6` | ۴۸۹ | ۵۹٫۷۱٪ | +۶٬۹۰۰$ | ۲۲ | ۸۵۰$ |
| `golden` | ۱٬۳۵۸ | ۵۵٫۷۴٪ | +۱۱٬۲۵۰$ | ۷۶ | ۲٬۴۰۰$ |
| `statistical` | ۲۰٬۶۶۱ | ۵۳٫۷۱٪ | +۱۴۰٬۱۵۰$ | ۱٬۱۸۵ | ۵٬۱۰۰$ |

(۱۲ ماهِ منتهی به ۲۰۲۶-۰۷-۲۵، قیمتِ ۵۰-۵۰، بدونِ کارمزد.)

هر پنجره حداکثر **یک** سیگنال از هر جریان می‌گیرد. اگر دیدی برای یک پنجره دو
سفارش از یک جریان ثبت شد، نسخهٔ `strategies.py` قدیمی است — دوباره بردارش.

## ۶) چیزهایی که ربات باید ثبت کند

## ۷) دام‌ها — این‌ها واقعاً اتفاق افتاده‌اند

1. **حفره در سریِ قیمت‌ها.** اگر ربات چند ساعت قطع شود و بعد قیمتِ جدید را به
   قیمت‌های قدیمی بچسبانی، آن شکاف مثل یک کندلِ غول‌پیکر خوانده می‌شود و
   بلافاصله سیگنالِ جعلی می‌دهد (یک بار پرشِ ۹۸۱ دلاری این‌طور خوانده شد). اگر
   بیش از ۲ پنجره جا افتاد، سری را دور بریز و از نو پر کن.
2. **قیمت‌ها باید فاصلهٔ دقیقاً ۵ دقیقه داشته باشند.** میکس‌کردنِ تایم‌فریم‌ها
   همهٔ آستانه‌ها را بی‌معنا می‌کند.
3. **بالای ۵۵ سنت وارد نشو.** با دقتِ ۵۷٪، لبه بالای ~۵۵ سنت می‌میرد. این
   بزرگ‌ترین فرضِ آزمایش‌نشدهٔ کلِ کار است — هیچ دادهٔ دفترِ سفارشی جمع نشده.
4. **سمتِ قرینهٔ قانون ۶ را اضافه نکن.** «RSI ≤ ۳۰ ← بالا» اندازه‌گیری شد:
   ۵۰٫۰۷٪، یعنی هیچ. یک‌طرفه بودنش عمدی است.
5. **قانون ۴ (AABA خالی) را به‌عنوان سیگنال برنگردان.** ۴۸٫۸٪ خارج از نمونه —
   زیرِ شیر یا خط. فقط به‌عنوان ورودیِ قانون ۶ وجود دارد.
6. **قانون ۶ در ۹۳٪ موارد خلافِ قانون ۴ را می‌گوید.** اگر دیدی جهتش با
   «ادامهٔ الگو» فرق دارد، درست کار می‌کند.

## ۸) انتظارِ واقع‌بینانه

۵۹٫۷٪ روی همان داده‌ای است که قانون ۶ از آن **پیدا** شده (جستجوی ۱۱۴ شرطی).
عددِ آینده کمتر خواهد بود. `سودِ هر چرخه = پایه × (۱ − ۸×(۱−p)³)`:

| دقتِ واقعی | سود سالانه (پایه ۵۰$) |
|---|---|
| ۶۰٪ | +۷٬۵۰۰$ |
| **۵۷٪** | **+۵٬۷۰۰$** |
| ۵۵٪ | +۴٬۳۰۰$ |
| ۵۰٪ | ۰$ |

مارتینگل لبه نمی‌سازد؛ با قیمتِ ۵۰-۵۰ هر دقتی بالای ۵۰٪ سودده است، چه با
مارتینگل چه بدون. مارتینگل فقط شکلِ نوسان را عوض می‌کند: سودهای کوچکِ مکرر در
برابر ضررهای بزرگِ نادر.

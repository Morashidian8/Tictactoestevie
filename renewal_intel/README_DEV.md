# Renewal Intelligence — راهنمای توسعه

دستیار کارگزاری بیمهٔ درمان تکمیلی (فارسی، راست‌به‌چپ). کاملاً در مرورگر اجرا می‌شود؛ سرور ندارد و فایل‌های
کارفرما از دستگاه بیرون نمی‌رود. نسخهٔ منتشرشده: https://morashidian8.github.io/Tictactoestevie/renewal/

> برای هوش مصنوعی یا برنامه‌نویسی که ادامه می‌دهد: این فایل را کامل بخوانید، بعد `src/` را. همهٔ متن‌های اپ
> فارسی‌اند؛ کد و نام‌ها انگلیسی. قبل و بعد از هر تغییر `src/smoke_test.py` را اجرا کنید.

## ساختار

```
renewal_intel/
  src/                 ← سورس اصلی (فقط این‌ها را ویرایش کنید)
    build.py           ← ساخت index.html و site/ از سورس‌ها
    smoke_test.py      ← آزمون خودکار (همهٔ صفحه‌ها، موبایل و دسکتاپ، تحلیل خسارت، صدور پیش‌نویس)
    ui2.shell.html     ← HTML پوسته + همهٔ CSS (تم روشن/تیره، نسخهٔ موبایل)
    engine.src.js      ← موتور تحلیل تمدید از اکسل قرارداد (Loss Ratio، سناریوها، بودجه)
    samples.src.js     ← گروه‌های نمونه (ساختگی)
    tender.src.js, tenders.src.js ← برآورد قیمت مناقصه
    docread.src.js     ← خواندن PDF (متنی/اسکن)، عکس، Word، اکسل سقف تعهدات؛ OCR فارسی روی دستگاه
    amount.js          ← خوانندهٔ اعداد فارسی (۰ نقطه‌ای، جداکننده‌ها) برای OCR
    lexicon.src.js     ← اصلاح غلط‌های OCR با واژه‌نامهٔ بیمه
    extract.src.js     ← فهم بیمه‌نامه: بیمه‌گذار، سال، نفرات، حق‌بیمه، فرانشیز، سقف هر پوشش (CCAT)
    ai.src.js          ← دستیار آفلاین (قاعده‌محور)
    docs.ui.js         ← صفحهٔ «مدارک و قراردادها»: بازبینی ردیف‌به‌ردیف، مقایسهٔ دو سال
    claims.ui.js       ← صفحهٔ «تحلیل خسارت»: مدل هزینه، بسته‌ها، تغییر پوشش‌ها، پیش‌نویس بیمه‌نامه، اکسل
    ui2.app.js         ← هستهٔ رابط: state، مسیریابی go()، خانه، منو، بارگذاری فایل
    sample.json        ← دادهٔ نمونهٔ پرتفوی (ساختگی)
  index.html           ← خروجی build.py (یک فایل؛ کتابخانهٔ اکسل از CDN)
  pwa/                 ← پوستهٔ اپ گوشی: head.html، manifest.json، sw.js، icons، fonts، vendor (xlsx، Tesseract، pdf.js)
  desktop/build_usb.py ← نسخهٔ رمزدار و تاریخ‌دار برای فلش (کد فعال‌سازی را هرگز commit نکنید)
```

## ساخت و اجرا

```bash
python3 renewal_intel/src/build.py --site          # index.html و site/ (مثل نسخهٔ منتشرشده)
cd renewal_intel/site && python3 -m http.server 8000   # http://localhost:8000
```
خواندن PDF و عکس با `file://` کار نمی‌کند؛ از سرور محلی بالا استفاده کنید.

آزمون:
```bash
pip install playwright openpyxl && python3 -m playwright install chromium
python3 renewal_intel/src/smoke_test.py               # باید OK چاپ کند
```

## انتشار

`.github/workflows/pwa.yml` با هر push روی `main` که `renewal_intel/**` را تغییر دهد، `site/renewal/` را می‌سازد:
`pwa/head.html` + `index.html` (کتابخانهٔ اکسل به `vendor/` محلی) + manifest، sw، icons، vendor، fonts.
بعد از هر تغییر، نسخهٔ کش را در `pwa/sw.js` یکی بالا ببرید (`renewal-intel-vN`) تا گوشی‌ها نسخهٔ جدید را بگیرند.
روال این پروژه: کار روی شاخهٔ جدا، و فقط پوشهٔ `renewal_intel` با اجازهٔ صاحب پروژه روی `main` می‌رود.

## مفاهیم مهم

- **واحدها:** داخل اپ همه‌چیز «میلیون تومان»؛ بیمه‌نامه‌ها ریال‌اند (`/1e7`). خسارت‌ها در اکسل سامانهٔ بیمه‌گر ریال.
- **کلیدهای پوشش (CCAT در extract.src.js):** `hosp` بستری، `special` جراحی‌های خاص، `delivery` زایمان، `infert` نازایی،
  `para` تصویربرداری، `diag` تست‌های تشخیصی، `lab` آزمایش، `fetal` غربالگری جنین، `outsurg` سرپایی، `rehab` فیزیوتراپی،
  `dental`، `visit`، `drug`، `visitdrug`، `emergency`، `glasses`، `refractive` لیزیک، `ambIn/ambOut` آمبولانس،
  `combo` سقف مشترک چند ردیف، `total` حداکثر تعهد سالانه.
- **قرارداد ذخیره‌شده:** `{id, src, org, insurer, year, plan, premium (هر نفر، م.ت), insured, franchise, caps:{key: م.ت}}`
  در `state.contracts`. `src` شناسهٔ سند خوانده‌شده در `state.docs` است (ردیف‌ها و متن برای پیش‌نویس).

### مدل هزینه (claims.ui.js)
- خسارت هر پوشش از اکسل خسارت (`parseClaims`، ستون‌های «گروه بیماری» و «مبلغ خسارت»؛ گروه‌ها با `CLM_MAP` به کلید پوشش).
- خسارت سال بعد = خسارت × (۱+خسارت دیررس) × (۱+تورم) × (۱+اثر سقف).
- **اثر سقف** (`capUplift`): اگر میانگین مصرف هر نفر نزدیک سقف قبلی بوده، بالا رفتن سقف (به ارزش واقعی، یعنی سقف ÷ (۱+تورم))
  هزینه را بالا می‌برد؛ پایین آمدن آن هزینه را کم می‌کند. سقف ۰ یعنی حذف پوشش.
- حق‌بیمه = خسارت سرانهٔ مورد انتظار ÷ Loss Ratio هدف (`costOf`، `priceOf`).
- اعتبارسنجی: برای فولاد کاویان ۱۴۰۵ با تورم ۴۰٪، خسارت دیررس ۱۰٪ و LR ۸۰٪، مدل برای سقف‌های بیمه‌نامهٔ واقعی
  دقیقاً همان ۲۳٫۴ میلیون بیمه‌گر را می‌دهد.

### بسته‌های سال بعد (`claimsPackages`)
- `real` «تحلیل واقعی» (پیشنهاد اپ): بی‌استفاده‌ها حذف، کم‌استفاده‌ها سقف کمتر، پرمتقاضی‌ها و پرشده‌ها بیشتر، بستری/جراحی خاص با ارزش واقعی.
- `opt` «به نفع بیمه‌گر»: همان نرخ؛ بندهای پرتکرار حداکثر هم‌پای تورم، سقف‌های بزرگ و کم‌تکرار بالا (روش بیمه‌گرها در مناقصه).
- `ins` پیشنهاد بیمه‌گر (اگر بیمه‌نامهٔ سال بعد داده شود)، `custom` سفارشی (تیک‌های «تغییر پوشش‌ها»).
- «بسته‌های دیگر»: `keep`، `bal`، `full`، `emp` (به نفع کارکنان).
- هر کارت: پرداخت واقعی به هر نفر، سهم بیمه‌گر، و حساسیت (LR اگر مصرف پرمتقاضی‌ها ۲۰٪ بالا برود).

### پیش‌نویس بیمه‌نامه (`proposalDoc`)
- قالب بیمه‌نامهٔ صادرشدهٔ بیمه‌گر (کادرهای مشخصات، جدول تعهدات با ترتیب ردیف‌های ۱ تا ۱۲ و سقف‌های مشترک، شرایط خصوصی، صورتحساب اقساط).
- عمداً بدون لوگو، QR و مهر بیمه‌گر و با برچسب «پیش‌نویس»: سند کارگزار است، نه سند صادرشدهٔ بیمه‌گر.
- چاپ در یک iframe جدا (`printDoc`)؛ Word به‌صورت HTML با پسوند ‎.doc.

### خواندن اسناد (docread.src.js)
- PDF متنی: متن مستقیم؛ اگر لایهٔ متنی خراب باشد (`drTextSane`) با OCR خوانده می‌شود.
- اسکن/عکس: Tesseract.js 5.1.1 (fas + eng) روی دستگاه؛ خطوط جدول پیدا می‌شود و خانه‌ها جدا خوانده می‌شوند.
  مبالغ با `drAmount` (amount.js). عدد بعد از برچسب در متن (حق‌بیمهٔ هر نفر) با `drNumberAfter`.
- دادهٔ زبان به‌صورت base64 در `pwa/vendor/ocr/*.b64.txt` (هاست ‎.gz را سرو نمی‌کرد).

## قواعد

- هیچ فایل یا دادهٔ واقعی کارفرما (اکسل خسارت، بیمه‌نامه) را در مخزن یا اپ عمومی نگذارید.
- کد فعال‌سازی نسخهٔ فلش را هرگز commit نکنید.
- اعداد را با `fmtNum`/`fmtInt`/`fmtPct` نمایش دهید (ارقام فارسی).
- هر صفحه باید روی عرض ۳۶۰ تا ۳۹۰ پیکسل بدون اسکرول افقی باشد (smoke_test این را چک می‌کند).
